# Database migrations (Alembic)

Securi uses **Alembic** for schema versioning. Startup calls `migrate_schema()` → `alembic upgrade head`.

## Commands (from `backend/`)

```bash
# Apply all migrations
alembic upgrade head

# Current revision
alembic current

# New autogenerated revision after model changes
alembic revision --autogenerate -m "describe_change"
```

Set `DATABASE_URL` in `.env` (async URL is fine; Alembic uses `psycopg2` sync driver internally).

## Existing databases (pre-Alembic)

If your database was created by the legacy `migrate.py` loops and has **no** `alembic_version` table, either:

1. **Let startup migrate** — first `alembic upgrade head` is idempotent (`CREATE IF NOT EXISTS`), or
2. **Stamp without running DDL** — if you are sure schema matches head:

```bash
alembic stamp head
```

## CI / tests

`tests/conftest.py` runs `migrate_schema()` before integration tests.
